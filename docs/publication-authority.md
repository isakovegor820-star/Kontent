# Основания создания публикаций

Проверено по исходному снимку запуска и изменениям A2, 7 сентября 2026.

| Путь | Основание и граница | Сохранение и повтор |
| --- | --- | --- |
| Composer → `POST /api/publication-operations` | Действующее `content.publish`; текущий согласованный revision/hash. В личном проекте нажатие owner на добавление в календарь выполняет существующее self-approval. В команде используется редакционное согласование. | Неизменяемый snapshot, operation, posts, parts и outbox в одной транзакции. Unique lineage связывает повтор с одним approved revision. Publisher может выбрать время без изменения согласованного текста. |
| Старый `POST /api/posts/create` | Закрыт: после проверки сессии и origin возвращает `410 publication_operation_required`. Неиспользуемый `createRealPost` удалён из store. | Ничего не создаёт. Клиент возвращается к черновику. |
| Бот: быстрый пост | Сохранённые в превью draft version, revision ID и content hash; действующее `content.publish` проекта диалога. В личном проекте owner подтверждает показанную версию одним нажатием; в командном требуется согласование этой версии. | `scheduleBotDraftPublication`: решение, immutable revision, operation, post, parts, outbox и завершённый диалог сохраняются атомарно. Redis вызывается после commit. Повтор не создаёт новый пост. |
| Бот: согласование | `content.approve` (owner/approver), открытый запрос с неизменяемым revision/hash. Членство блокируется на время транзакции решения. | Решение и workflow сохраняются вместе с аудитом. Исправлена реальная ошибка PostgreSQL: явные bigint casts версий в audit insert. |
| Автопилот: web/bot confirm | Точный серверный preview token/hash, revision плана, явное подтверждение и собственные проверки качества. Совмещённое действие подтверждения и постановки требует `content.publish` (owner/publisher) в обоих интерфейсах. | Существующие approval operation, lease и `autopilot_schedule_outbox`; каждый item повторно проверяет и блокирует действующее право перед созданием post. Publisher может подтвердить план коллеги. Генерация сама посты не планирует (`fullAtCommit=false`). |
| RSS worker | Включённая политика ленты, конкретный новый RSS-item, активный канал того же проекта. Для legal opportunity требуется отдельный `auto_publish_enabled`. Это разрешённая автоматизация проекта; отдельное ручное согласование каждой новости не добавляется. | Feed/item блокируются; post, ссылка RSS-item и AI usage сохраняются транзакционно. При сбое Redis принятый post сохраняется; действующая минутная сверка восстанавливает revision-bound job. Вызов без RSS feed/item отклоняется. |
| Retry, восстановление outbox, системная сверка | Только уже сохранённые post/operation, project ID и schedule revision; не новый текст из запроса. | Существующие lease, attempt journal и правила неизвестного результата. Неизвестный результат отправки не превращается в автоматическую повторную публикацию. |
| Импорт Telegram stats/public posts | Наблюдение уже опубликованного внешнего сообщения. | Создаёт историческую запись, не scheduled-post и не задание отправки. |

`origin` — происхождение материала, а не разрешение публикации. Публичное тело запроса не может объявить себя RSS/Автопилотом, чтобы обойти согласование. Неиспользуемый серверный `schedulePost` без checkpoint удалён.

Превью бота ограничено одним текстовым Telegram-постом, как и прежний быстрый сценарий. Версия, изменённая в web после превью, отклоняется. Старые превью без revision/hash требуют повторной проверки черновика; сами черновики и уже созданные задания сохраняются.

## Проверка A2

На исходном коде на PostgreSQL воспроизведены все три дефекта: бот поставил изменённый непоказанный текст, бот поставил командный черновик без approval, старый API принял произвольный текст publisher с HTTP 200. После исправления те же три сценария проходят: `../evidence/a2-baseline-reproduction` и `../evidence/a2-baseline-cases-after`.

15 новых PostgreSQL-сценариев бота/Автопилота прошли (`../evidence/a2-bot-and-autopilot-integration`), включая право участника publisher, отзыв, смену выбора на другом устройстве, одновременные нажатия и Redis failure после commit. Пять существующих интеграционных сценариев publication operation прошли на отдельной БД (`../evidence/a2-web-integration`): multi-destination, частичная очередь, восстановление, конкурентный replay, неизменяемая версия. Types и lint изменённых файлов прошли (`a2-types-final`, `a2-lint`).

Полный unit-прогон: 589 файлов, 3185 тестов прошли (`../evidence/a2-unit-all-final`). Снижение числа тестов на четыре связано с заменой десяти тестов удалённого legacy-пути шестью проверками его закрытия; проверки действующего publication operation сохранены.

Команда новых интеграционных проверок: `npm run test:bot-publication:integration`. Она пересоздаёт public schema только в локальной одноразовой `aurora_launch_test`; guard такой же, как у проверки A1. Внешние отправки заменены fake очередью. Browser journeys, общий fault-injection и release gate относятся к A7; этот документ не объявляет production готовым.
