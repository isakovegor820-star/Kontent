# AI: текущий доступ к проекту

Платёжный учёт и допуск к данным — отдельные проверки. Каждый явно отнесённый к проекту вызов AI, включая бесплатный локальный Ollama, streaming и embeddings, проверяет действующее членство, разрешение `content.create`, отсутствие блокировки пользователя и архивирования проекта. Роли определяет общий `project-role-policy.mjs`. Локальный движок не требует денежных тарифов и не создаёт денежный расход. Платные попытки по-прежнему требуют явных тарифов/лимитов и удерживают расход при неизвестном результате; отказ доступа или лимита не маскируется как успешный embedding.

Задания Sites используют сохранённого инициатора: запрос повторной генерации, автора материала, инициатора отчёта или исходного задания анализа. Старый отчёт без инициатора и связанного анализа, задание probe/report без пользователя, анализ без проекта остаются без выполнения до новой авторизации. Личный проект или владелец сайта не подставляются для восстановления потерянного контекста. Автоматический scheduler явно передаёт фактического владельца сайта, после чего его текущие права проверяются тем же способом.

Чтение контекста и сохранение результатов выполняются в коротких транзакциях со shared locks на проекте, участнике, пользователе, сайте и, для анализа, исходном задании. Внешние запросы не держат эти блокировки. Граница допуска запроса линейризуется проверкой текущих прав: уже допущенный запрос может завершиться после отзыва, но новая попытка и сохранение результата требуют новой проверки. Поэтому результат, полученный после отзыва, не становится материалом, классификацией, ответом интервью или интерпретацией отчёта. Дежурный может видеть технический код отказа; это не основание автоматически восстанавливать членство или повторять задание от другого пользователя.

При `ai_work_scope_forbidden`/`ai_work_scope_required` проверьте текущую роль/блокировку/архивность и сохранённые идентификаторы задания. Для неоднозначного старого задания создайте новый запрос из проекта от действующего пользователя. Не меняйте старую атрибуцию на предполагаемую. Для отказов денежной политики используйте отдельную процедуру настройки бюджета; восстановление прав не отменяет ранее учтённый расход.

Миграции для этой проверки не нужны. Код должен быть включён и в web, и в worker; запуск старого worker сохраняет старый обход. Проверка: `MIGRATION_TEST_DATABASE_URL=postgresql://egor@127.0.0.1:57439/aurora_sites_ai_auth_test npm run test:sites-ai-current-access:integration` (только одноразовая локальная БД с этим именем). Набор использует синтетический HTTP и не подтверждает доступность, качество или стоимость настоящего провайдера.
