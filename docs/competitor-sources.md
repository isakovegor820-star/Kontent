# Источники конкурентов

## Общий контракт

`competitors.network` выбирает провайдер, а жизненный цикл у всех источников одинаковый:

- `pending` / `refreshing` — первичная или ручная синхронизация;
- `ready` — последняя синхронизация успешна;
- `error` / `no_feed` — источник недоступен с объяснением в `last_error`;
- `paused` + `is_active = false` — автоматические обновления временно отключены.

Посты имеют провайдер-независимые `external_post_id`, `permalink`, `like_count`,
`comments_count` и `thumbnail_url`. Telegram сохраняет совместимый `tg_msg_id`, поэтому
старые досье и аналитика продолжают работать. Для новой сети нужны адаптер сбора,
метаданные в `COMPETITOR_PROVIDERS` и парсер публичного идентификатора — API и карточки
переделывать не требуется.

## Telegram

Способ подключения:

1. `getChat` — название публичного канала.
2. `getChatMemberCount` — число участников, если Bot API возвращает его для канала.
3. Публичное превью `t.me/s/<handle>` — последние видимые публикации, время,
   просмотры и доступные реакции.

Ограничения:

- только публичные каналы; invite-ссылки и закрытые ленты не поддерживаются;
- Bot API не предоставляет универсальный метод чтения истории чужого канала;
- публичное превью может не показывать реакции и не даёт демографию, расходы,
  полный охват, достоверные пересылки или комментарии;
- HTML публичного превью может измениться, поэтому ошибки парсинга должны оставаться
  видимым статусом источника, а не пустым «успехом».

Официальная справка: [Telegram Bot API — getChat и getChatMemberCount](https://core.telegram.org/bots/api).

## Instagram

Способ подключения:

1. Пользователь подключает собственный Instagram Professional через Facebook Login.
2. Токен хранится в `oauth_tokens` в AES-GCM-конверте.
3. Воркер вызывает официальный Graph API `business_discovery.username(...)` от имени
   подключённого профессионального аккаунта и получает базовый профиль и последние
   медиа: подпись, дату, permalink, лайки и комментарии.

Нужные разрешения для текущего Facebook Login-потока: `pages_show_list`,
`instagram_basic`, `pages_read_engagement` (публикация дополнительно использует
`instagram_content_publish`). Внешний app review / Advanced Access может быть обязателен
для работы с профессиональными аккаунтами, которыми пользователь приложения не владеет.

Ограничения:

- доступны Instagram Business и Creator; consumer/personal-аккаунты не доступны;
- закрытый или неразрешённый профиль возвращает честную ошибку;
- требуется профессиональный Instagram-аккаунт пользователя и корректная связь с
  Facebook Page для используемого Facebook Login-потока;
- набор полей, лимиты и permissions меняются по версиям Graph API; версия задаётся
  `META_GRAPH_API_VERSION` (по умолчанию `v24.0`), base URL — `META_GRAPH_API_BASE`;
- скрейпинг Instagram не используется как fallback;
- токены и ошибки провайдера нельзя выводить в клиент или логи целиком.

Официальная справка: [Meta Instagram API collection](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api).

## Следующие провайдеры

- VK: официальный API сообщества/публичной страницы, токен и granular permissions.
- YouTube: YouTube Data API, OAuth, quota units и пагинация uploads playlist.
- Сайты и блоги: RSS/Atom в приоритете; HTML только через безопасный fetch, robots и
  явные лимиты частоты.

Новая интеграция не должна объявлять `ready`, пока не подтверждена хотя бы метаинформация
источника. Отсутствующие метрики остаются `null`, а не превращаются в нули.
