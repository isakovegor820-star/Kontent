# Аврора — исходная карта фактических возможностей

Срез сохранён до конференционных исправлений 16 сентября 2026 года. Статус «есть экран» здесь не равен статусу «функция работает». Browser evidence относится только к отдельной QA-базе, синтетическим пользователям и локальному production-like runtime; реальные внешние отправки не выполнялись.

## Аудитория и назначение

Аврора — рабочий контур для подготовки, планирования, проверки, согласования и публикации контента. Для юриста она помогает вести редакционный процесс и сохранять основания формулировок; для фирмы — разделять проекты и роли; для SMM — управлять материалами и календарём. Это не CRM, не система ведения дел, не хранилище клиентских досье и не замена юридической экспертизы.

## Роли и неизменяемые правила

- Пользователь принадлежит проекту как `owner`, `author`, `approver` или `publisher`; сервер проверяет project scope и права.
- В проекте должен оставаться хотя бы один активный владелец.
- Автор готовит версии; согласование относится к точной версии; опубликованный материал не должен незаметно меняться.
- Публикацию и изменение публикации могут выполнять только разрешённые роли и только через серверную операцию с идемпотентностью, очередью и историей.
- Контекст выбранного проекта подтверждается сервером; localStorage не является источником полномочий.
- Финальное юридическое решение принимает человек. Отсутствие источника или AI-проверки не может превращаться в положительное заключение.
- Telegram/VK, AI, внешнее исследование, почта, object storage и наблюдаемость зависят от конфигурации среды; UI не доказывает их доступность.

## Внешние зависимости

| Зависимость | Что от неё зависит | Состояние QA |
|---|---|---|
| PostgreSQL | аккаунты, проекты, черновики, настройки, операции | Изолированная база работала |
| Redis + BullMQ worker | публикации, RSS, Autopilot, analytics, media/site jobs | Worker работал; отсутствие ошибок очереди не доказывает завершение каждой job |
| Telegram Bot API | подключение, проверка, публикация, метрики | Live credentials/send не использовались |
| VK API | подключение/публикация | Не настроен и не проверен |
| AI providers / Ollama | Studio, generation, semantic processing | Внешние ключи отсутствуют, локальный Ollama недоступен |
| Search/RSS/site providers | Radar, Trends, RSS, site analysis | Полное покрытие не проверено |
| S3-compatible storage | Uploads/media | Не проверено внешним объектным хранилищем |
| Mail | recovery/invitations | Реальная доставка не выполнялась |
| Sentry | observability | Отключён в isolated E2E/QA; наличие SDK не доказывает production monitoring |

## Покрытие браузерных операций

Подтверждены: создание аккаунта; field validation; создание/переключение/переименование проекта; timezone persistence; серверный черновик и reload; project isolation; сохранение текстового правила; навигация/deep link/back по основным разделам; narrow viewport 320/390; базовая клавиатура; несколько empty/error states.

Не подтверждены: удаление/архивирование большинства сущностей; принятие приглашения и отзыв доступа независимым пользователем; полный role matrix; end-to-end approval; реальный экспорт-файл; live Telegram/VK; AI quality; полные search/filter/sort/pagination; multi-tab concurrency; все retry/recovery ветви; DSAR/delete-account; production load/capacity.
