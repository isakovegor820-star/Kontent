# Перенос постов автопилота в основном календаре

Реализовано в ветке `codex/calendar-autopilot-drag` на базе `e5c2ec6`.

Запланированный пост автопилота с подтверждённой связью с планом можно переносить мышью в недельном календаре и через выбор дня с клавиатуры. Время сохраняется в часовом поясе календаря. Новая публикация не создаётся.

## Изменения

- API календаря возвращает доступность переноса и числовую версию расписания поста.
- Перенос обновляет существующий пост, план и outbox в транзакции; синхронизированный черновик обновляется вместе с ними. Несинхронизированные правки редактора сохраняются, а устаревшая привязка блокирует их случайную запись поверх переноса.
- Для изменения времени уже запланированного поста требуется право публикации. Право редактирования непоставленного плана проверяется отдельно. Проверки повторяются под блокировкой членства в проекте.
- Поддерживаются посты из завершённых планов, пока их действующая связь с планом и outbox сохранена. Отправляемые, опубликованные и отменённые посты не переносятся.
- Ответ сервера содержит подтверждённое расписание и новую версию. Карточка обновляется сразу; устаревший ответ загрузки не возвращает её на прежнее место. Обновляется и общий список публикаций для других экранов.
- После потери ответа клиент читает фактическую дату без повторения PATCH. Если результат нельзя установить, интерфейс сообщает неопределённость. Сохранённая дата при недоступной очереди не откатывается; задание восстанавливается через outbox.

## Проверено

- 64 модульных/компонентных проверки в 9 файлах: календарь, контроллер жеста, часовые пояса, подтверждение/потеря ответа, поздние ответы загрузки, API постов, очередь и защита отправки.
- 31 интеграционная проверка в 3 файлах на отдельной PostgreSQL 17 с полной схемой проекта. Новые 15 сценариев включают реальные блокировки при конкурирующих переносах, захвате поста worker и отзыве прав, изоляцию проектов, старые планы, DST, чистый и изменённый редактор, открытие редактора после переноса и откат транзакции.
- На отдельной Redis проверено восстановление через outbox: старое и новое задания действительно обрабатываются BullMQ worker с настоящими функциями захвата публикации. Подставной внешний провайдер получает ровно одну отправку. Внешние публикации не выполнялись.
- В Chrome через настоящий компонент календаря: перенос карточки со среды 10 апреля 2030 на четверг 11 апреля, сохранение 12:00 Europe/Amsterdam, один PATCH, отсутствие открытия редактора, сохранение после перезагрузки. Проверены также перенос с клавиатуры на пятницу и отпускание в том же дне без запроса. Окончательный код повторно проверен переносом мышью после подключения обновления общего списка публикаций.
- Браузерный стенд использует синтетические HTTP-ответы; работа настоящего API и базы проверена отдельными интеграционными тестами. Это не проверка работающего production-сайта. Сенсорный жест проверен на уровне контроллера, без физического телефона.
- TypeScript, ESLint изменённых файлов и `git diff --check` прошли.
- Production-сборка `node scripts/build.mjs` прошла на точных зависимостях из lock-файла: webpack, TypeScript и генерация всех 248 статических страниц. Первую попытку с заимствованными зависимостями остановило отсутствие шрифта Onest; после отдельного `npm ci --ignore-scripts --no-audit --no-fund` сборка завершилась успешно.

Артефакт `browser-state.json` содержит запрос окончательного браузерного прогона и сохранённую дату тестового поста.

```sh
node node_modules/vitest/vitest.mjs run src/lib/calendar-autopilot-reschedule.test.ts src/lib/calendar-drag-reschedule.test.ts src/lib/calendar-long-press-drag.test.ts src/lib/use-calendar-data.test.tsx src/app/api/posts/route.test.ts src/app/app/calendar/page.test.ts worker/publication-lease.test.mjs worker/publication-safety.test.mjs src/lib/autopilot-scheduling.test.mjs --maxWorkers=1
```

Интеграционные тесты намеренно требуют отдельную PostgreSQL на `127.0.0.1:55437` с pgvector и отдельную Redis на `127.0.0.1:56437`. Они создают синтетические данные; новый набор создаёт и удаляет собственную временную БД.

```sh
DATABASE_URL=postgresql://postgres@127.0.0.1:55437/postgres node node_modules/vitest/vitest.mjs run --config vitest.integration.config.ts src/e2e/calendar-autopilot-reschedule.integration.ts src/e2e/autopilot-editor-isolation.integration.ts src/e2e/calendar-pagination.integration.ts --maxWorkers=1
```

Для изолированной проверки интерфейса: `node scripts/preview-calendar-autopilot-drag.mjs`, затем `http://127.0.0.1:3317/#calendar-real-12001`. Это тестовый стенд с синтетическими данными, не полный dev runtime.

На рабочий сайт изменения не выкладывались; production-данные не менялись. Перетаскивание внутри отдельного календаря автопилота и в режиме «Месяц» не входило в объём этой задачи.
